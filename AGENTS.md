# AGENTS.md

Guidance for AI coding agents working in this repository.

## Project Overview

Personal website for Eliza Hamilton ([jeanmachine.dev](https://jeanmachine.dev)). Also hosted at ([eliza.vg](https://eliza.vg)).

- **Framework:** SvelteKit 2 + Svelte 5 (runes) + TypeScript, built with Vite 7
- **Hosting:** Cloudflare Pages via `@sveltejs/adapter-cloudflare` (config in `svelte.config.js` and `wrangler.toml`; output goes to `.svelte-kit/cloudflare`)
- **Integrations:**
  - **AT Protocol:** proxies to the owner's PDS (`pds.jeanmachine.dev`) under `src/routes/api/atproto/*`; blog publications and document envelopes remain `site.standard.*` records on the PDS. Envelope schemas and types come from `@atcute/standard-site`; the document body extension uses `@atcute/leaflet`. Validation uses `@atcute/lexicons`; no local lexicon copies are needed.
  - **GitHub:** contribution calendar + language stats via the GitHub GraphQL API (`src/lib/server/github.ts`), served from `src/routes/api/github/*`.

## Commands

**Bun is the package manager** (pinned via `packageManager: bun@1.4.3`, lockfile is `bun.lock`, Dependabot uses the `bun` ecosystem). Use `bun` / `bunx`, not `npm` / `npx` / `pnpm`.

```bash
bun install        # install dependencies (runs svelte-kit sync via "prepare")
bun run dev        # Vite dev server (bun run dev -- --open to open a browser)
bun run build      # production build -> .svelte-kit/cloudflare (adapter-cloudflare)
bun run preview    # preview the production build
bun run check      # svelte-kit sync + svelte-check (THE validation gate)
bun run check:watch
```

- **Focused blog tests:** `bun test src/lib/blog src/lib/server/blog.test.ts src/lib/server/blog-example.test.ts`. `bun run check` (svelte-check, strict TS) remains the primary validation gate.
- **`vite build` does not type-check.** Always run `bun run check` after edits — the build succeeding does not mean types are clean.
- **Formatting:** Prettier (`.prettierrc`, `prettier-plugin-svelte`): `bun run format` to write, `bunx prettier --check .` to verify. Style: single quotes, 2-space indent (no tabs), 80 print width (150 for HTML files), trailing commas, semicolons.
- **No ESLint.** Don't introduce it ad hoc.
- **Local Workers runtime (optional):** `bunx wrangler pages dev` against the adapter output. Note wrangler writes logs to `~/Library/Preferences/.wrangler/logs/` — in sandboxed environments this fails with `EPERM`, which is noisy but benign.

## Deployment

- **Cloudflare Pages Git integration:** pushes are built with `bun run deploy` (= `bun install && vite build`) and served from `.svelte-kit/cloudflare` (per `wrangler.toml`). No `wrangler` commands are run from this repo.
- The plan is to **stay on Cloudflare Pages** — do not migrate to Workers/static assets or swap adapters.

## Environment & Secrets

- Copy `.env.example` to `.env` for local development. `.env` is gitignored and must never be committed.
- `GITHUB_TOKEN` (GitHub PAT) is required by `src/lib/server/github.ts`; it is read from `$env/dynamic/private` at request time, so it is a **runtime secret** on Cloudflare, not a build-time variable. Server code must therefore be dynamic-env friendly (no `import.meta.env` for secrets).
- Server code runs on the **Cloudflare Workers runtime (workerd)**, not Node — use Web APIs (`fetch`, `URL`, etc.). Don't import Node-only modules into server code.

## Architecture Notes

- `src/lib/constants.ts` — central config: PDS URL, DID, publication rkey, social links, GitHub username, and repo/language exclusion lists for the language stats.
- `src/lib/server/*` — server-only modules (GitHub GraphQL client).
- `src/routes/api/atproto/*` — thin GET proxies to PDS XRPC methods (`blob`, `listRecords`, `record`, `resolve`, `postview`). Some set `Cache-Control: public, max-age=3600`; the GitHub endpoints use `no-store` in dev and `max-age=1800` in prod. Preserve these cache headers.
- `src/routes/blog/*` — blog listing and native article reader backed by `site.standard.document` and `site.standard.publication` records fetched from the PDS. This website is the primary, canonical blog, not a read-only mirror of Leaflet. Leaflet supplies the document body extension, not the source of truth or publication styling; the reader uses this site's styles.
- `src/lib/components`, `src/lib/icons` — UI components and single-file Svelte icons; re-exported via `index.ts` barrels.
- `src/routes/blog/[rkey]/+page.svelte` — native article route keyed by document record key; the route owns article head metadata and uses this website's article URL as canonical. The route-to-`Article` contract is `{ document, publication, rkey }`, without an `originalUrl` prop or an external-source link. The root layout suppresses default title/description/OG/Twitter metadata on this route, restores `<title>{NAME}</title>` on non-reader routes, and keeps the favicon global.
- Native article layout — use a shared header card and one distinct shared `.card.article-page` per top-level Leaflet page (linear pages and accessible canvas flows), all full-width within the shared layout with 10px gaps instead of page separator lines. `.article-body` is an unstyled full-width wrapper, not an enclosing card; do not nest translucent card fills or style nested linear groups as cards. `Content` normalizes once and accepts optional `before`/`after` Svelte snippets: Article supplies the existing cover only inside the first page card and the footer only inside the last. Plain-text fallback or no readable content uses one shared fallback card containing both snippets; do not create separate cover/footer cards. Preserve page IDs, page links, block order, canvas and truncation notices, and standalone Content usage. Size drawing SVGs explicitly, never all `.blog-content svg`, so the footer chevron keeps its icon dimensions; normal images and preview images use the media sizing rules. There is no top navigation card; the only “Return to blog” link is in the footer with a decorative left `ChevronLeft` icon. Do not display the publication name in the article header. Use the standard shared card translucency (`color-mix(in srgb, var(--base) 80%, transparent)`) without an article background override, preserving its border, radius and standard padding. The article body itself stays transparent with no additional fill. On mobile the root content scroller supplies the standard fill; do not add a second background layer. Do not add a bounded article container, inner readability panel, prose width cap or extra wrapper padding. Blog articles, Work and Credits use whole-page document scrolling on desktop, without bounded cards or nested page scrollers; mobile preserves the fixed root layout and its content scroller. Preserve meaningful block-specific backgrounds such as code and highlights.
- Embed behavior — Bluesky and owned Standard Site previews start with safe SSR links and progressively load public metadata after client mount through same-origin APIs: referenced Bluesky author/text/date, owned document/publication title/description with native `/blog/<rkey>` and `/blog` links. Unavailable previews keep safe links; foreign Standard Site records keep PDSls fallbacks. Embed and website cards share the homepage Post's `.post-card` frame from `src/lib/components/post-card.css` (overlay border, 16px radius/padding, 12px gap, translucent surface), but only the homepage retains its 30rem cap and Pinned override. Article-only geometry/typography lives in `content.css`: 48px author/publication identities, 20px provider badges, wrapping author/date and full-width cards without nested scrollers. Bluesky uses the referenced author's DID/profile/avatar, escaped text, validated public images/external cards and available stats, never the owner's identity or fabricated quotes; keep an accessible primary post link. Standard Site branding requires a valid exact document/publication collection, not a label prefix; always use the local `/assets/standard-site-favicon.png`, as a 48px fallback or 20px badge alongside an available publication icon. Poll fallbacks must not acquire Standard Site branding. Website cards use only authored Leaflet title/description/PDS blob fields, not arbitrary remote URL scraping; only exact hostname `standard.site` gets the local provider favicon. Keep failed-media fallbacks, lazy decoding, no-referrer media and validated CDN/PDS-only image sources; scope identity sizes above general article image rules, and preview selectors only to real preview media. Poll interaction remains explicitly unavailable, not a functional poll. The local `/blog/example` fixture uses real public references without PDS writes; retain dev-only/no-store/production-404 gating and the existing PDS blob image proxy.
- External video — `Iframe.svelte` shares `.post-card` and stays click-to-load with no provider thumbnail/API/script requests before consent. Keep `safeFrameUrl` restricted to exact external HTTPS YouTube-nocookie `/embed/` and Vimeo `/video/` URLs, never raw HTML or arbitrary frames. After consent only, use `strict-origin-when-cross-origin` (origin, not article path/query; avoids YouTube error 153) and sandbox `allow-scripts allow-same-origin allow-presentation`, with encrypted-media/fullscreen/picture-in-picture permissions and no added autoplay. External provider origins cannot access the parent DOM; do not add forms/popups/top-navigation/storage-access grants. Explain origin/IP sharing and provider storage. Reset consent on source changes/unmount; retain canonical YouTube watch/Vimeo links without JavaScript and on failure, never infer playback from iframe load. Video-only CSS keeps YouTube 16:9/min-height 200px and clamps authored Vimeo heights responsively; leave website right thumbnails and other embed/homepage identities unchanged. The dev fixture uses Rick Astley's official “Never Gonna Give You Up”.
- Code syntax — `src/lib/blog/highlight.ts` uses synchronous, lazily initialized Shiki core with the JavaScript regex engine (no WASM/Node runtime), selected public grammar modules and their embedded dependencies, and Catppuccin Latte/Frappe. Keep SSR and standalone Content hydration deterministic. Render escaped Svelte token spans, never source HTML; only foreground colors use `light-dark()`, preserving existing backgrounds, typography, native Unicode emoji and keyboard scrolling. Preserve original text/separators and trailing blank lines (HTML parsing normalizes CR line endings). Keep code/line/line-count/token limits and the bounded cache; unknown/missing languages or excess/error cases fall back to the entire escaped source. Do not import full language bundles or fetch grammars at runtime.
- `src/routes/+layout.svelte` and `src/index.css` — a decorative fixed background layer derives reading mode from `page.route.id === '/blog/[rkey]'` during SSR and client navigation. Articles and all reduced-motion users get `static/assets/background-still.webp` (the GIF's first frame, same dimensions and centered cover crop); only non-reader routes with `prefers-reduced-motion: no-preference` select `background.gif`. This replaces the animation rather than covering or pausing it; no client-only initialization or session-global state is needed.
- Emoji stay native Unicode text (including SSR, rich-text byte offsets, code and dynamic updates). `src/index.css` self-hosts the unmodified official Google `static/fonts/NotoColorEmoji/Noto-COLRv1.b8e25ea6.ttf`, with no CDN or per-emoji image requests. Its pinned upstream commit, SHA-256, copyright and update guidance are in that directory's `README.md`. Fontsource 5.3.2's WOFF2 subsets load/select but paint blank on macOS Helium 155 and Chrome 156; its WOFF fallback and this upstream TTF paint correctly. Validate actual screenshot pixels when updating, not just font names or successful loads. The shared `--font-site` stack is Maple Mono, Noto Color Emoji, then the existing monospace fallbacks; use it in `main`, `.native-article` and `.blog-content`. Maple stays first to preserve prose, ordinary digits and punctuation, while Noto precedes generic/system emoji fallback. Inherited `font-variant-emoji: normal` keeps normal author-font selection (Maple for plain ASCII, Noto for supported emoji); Chromium's `unicode` or `emoji` values can bypass the author emoji font and select platform emoji instead. Preserve explicit text/emoji presentation selectors and sequences as native Unicode; do not add DOM conversion, wrappers or global font overrides that affect math or controls. Noto uses COLRv1, declared with `tech(color-COLRv1)` so unsupported browsers can skip the font and use platform emoji. Credits link Google's Noto project and the unmodified upstream OFL at `static/fonts/NotoColorEmoji/LICENSE.txt`; keep that license and the font's copyright/provenance in distributed output.
- `.gitignore` entries for `static/backgrounds/` ("Protected Assets") and `*.zed/` / `*.vscode/` / `*.claude/` are leftovers from an earlier iteration; nothing in `src/` references them.
- `tsconfig.json` extends the generated `.svelte-kit/tsconfig.json`; route `$types` imports are generated by `svelte-kit sync` (run automatically by `bun run check` / `bun install`). If type imports for new routes fail, run sync first.

## Known Quirks

- `package.json` has `"resolutions": { "rollup": "npm:@rollup/wasm-node" }`. The original reason is unclear, but it **is active** (Bun resolves `rollup` to the WASM build) and builds/deploys work with it — leave it in place unless deliberately reworking build tooling.
- No CI workflows exist — only Dependabot (weekly, all deps grouped). Validation happens locally via `bun run check` and `bun run build`.
